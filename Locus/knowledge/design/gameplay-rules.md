# 玩法规则与状态设计（P1 规格）

> BoxPushing 底层玩法（Domain）的规则与状态建模决策。实现为 `BoxPushing.Core` 纯 C# 逻辑；基础架构见 README 与 `design/architecture-decisions.md`。

## 1. 状态建模

- `GameState` 持有 `LevelData` 引用 + 动态状态，不复制静态数据（墙/地板/目标始终来自 `LevelData`）。
- 动态状态 = `PlayerPosition`（GridPosition）+ `BoxPositions`（无序集合，箱子可互换）+ `Facing`（Direction）。
- 撤销只涉及动态部分。
- 朝向计入状态：随成功移动更新为移动方向，撤销时一并恢复；初始朝向默认 Down（可调）；无原地转向动作；阻塞的尝试不改变朝向与状态。

## 2. 移动规则

- 标准 Sokoban：仅推不拉；一次只推一个箱子；玩家前方是墙，或箱子再前方是墙/箱子 → 整步阻塞；玩家可进入地板/目标格。
- 一步 = 一次方向输入 = 一个命令（撤销粒度）。
- 新增 `Direction` 枚举（Up/Down/Left/Right）。GridPosition：X 为列、Y 为行；Up=(0,-1)、Down=(0,+1)、Left=(-1,0)、Right=(+1,0)。

## 3. 胜负判定

- 每步成功移动后判定：所有目标被箱子占据（校验保证箱数==目标数，等价于所有箱子落目标）。
- P1 不做死局/不可解检测（后置，并入 Solver 阶段）。

## 4. 撤销 / 重做

- 命令模式 + 双栈（undo / redo）。
- 命令记录 `GameState` 一步内产生的差分：玩家 from/to、若有推箱则箱 from/to、朝向 from/to。
- 仅成功移动入栈；无效尝试不产生命令、不改变状态。
- 撤销后重做栈可用；新移动清空重做栈。
- 胜利后允许撤销（撤销后重新判定胜负）。

## 5. Domain API 契约

- `TryMove(Direction)` 瞬时原子，返回结构化结果（是否成功、是否推动箱子、是否达成胜利）。
- Domain 不处理动画/节流；表现层负责动画播放与输入节奏。

## 6. 输入（P3 实现，方向已定）

- 键盘/手柄：长按连发；触摸：轻点走一格。
- 键盘/手柄连发速率受限：每步之间保留最小时间窗口（初始延迟 + 步间间隔），确保玩家可随时精确停下。

## 7. 校验与可达性

- `LevelValidator` 静态校验：恰好 1 玩家、箱数==目标数、边界闭合、非矩形防御、拒绝 XSB 字符集外字符。
  - XSB 字符集本身已排除"玩家/箱子落墙"与"玩家箱子重叠"（单字符无法表达），故不额外校验这两项。
- BFS 可达性：① 玩家连通性（忽略箱子，检查所有非墙格可达）+ ② 每个箱子可达（玩家能走到其相邻格）。
- 完整 Solver（全解判定）后置。
